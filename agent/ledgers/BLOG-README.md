# Blog workspace

```
Blog/
  AUTHORED-POSTS.md         the 49 posts written in this engagement: date,
                            status, slug, title, batch. A record for auditing
                            their performance later. Hand maintained.
  LEDGER.md                 blog posts: what changed, when, why, when judgeable.
                            GENERATED by ledger.py render. Never hand edit.
  archive/                  shipped drafts (compressed) and the full change log
  data/                     manifests, baselines, the ledger JSON
```

**`LEDGER.md` is generated.** Blog post changes go through `ledger.py note`, then `ledger.py render`. Anything typed into the file by hand is lost on the next render.

**Once a post reaches the CMS its draft is archived, not kept loose.** The
article body then lives in the CMS, which is the source of truth; the parts that
exist nowhere else - keyword strategy, competitor gap analysis, CTA copy, image
briefs - are preserved in `archive/shipped-drafts-YYYY-MM.tar.gz`. Restore with:

```bash
tar xzf Blog/archive/shipped-drafts-2026-08.tar.gz -C /tmp
```

## The ledger — read this before refreshing anything

`LEDGER.md` records every change to every post: what, when, why, and the
Search Console baseline it should be judged against. Its job is to stop the same
page being rewritten twice in one measurement window, which makes both changes
unmeasurable.

```bash
python3 ledger.py check <slug>   # may I touch this page? exits 1 if not
python3 ledger.py due            # which changes are ready to be judged
python3 ledger.py backfill       # rebuild history from the API (idempotent)
python3 ledger.py render         # regenerate LEDGER.md
```

Cooling-off is 90 days for a content change, 60 for internal links, 30 for
metadata or a hero swap. Those are how long the effect takes to read, not
arbitrary limits.

## data

`data/` holds what must survive: upload manifests (the record of what is live on
the CDN), the Search Console baseline, the ledger, and the Unsplash credits file
— that last one is a licence obligation, not a convenience.

## Internal linking toolchain

Lives in `tools/blog-visuals/`. Run in this order:

```bash
python3 link_audit.py      # measure the current graph
python3 mine_phrases.py    # find phrases that recur in real prose
python3 propose_links.py   # propose links, capped and scored
python3 review_links.py    # read them in context BEFORE pushing
python3 apply_links.py     # splice + verify four invariants
python3 push_links.py      # dry run; --limit 1, then --go, --revert to undo
```

Two rules the code enforces so they cannot be forgotten:

- **The HTML is never re-parsed and re-serialized.** BeautifulSoup decodes
  `&nbsp;`, and `Post.save()` injects heading anchor ids with a raw substring
  test, so a parser round-trip silently strips ids and takes the table of
  contents with them. Insertion is offset splicing on the original string.
- **Active posts are rewritten through `PostRevision`, never a direct save.**
  The post stays Active throughout and `previous` makes every change revertible.
